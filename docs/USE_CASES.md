# LEMIT 유스케이스

> 기능별 사용 시나리오와 완료 기준을 정리한 문서입니다. 각 유스케이스는 GitHub 이슈 하나와 1:1로 연결됩니다.
> 기획 배경은 [PROJECT_PLAN.md](PROJECT_PLAN.md), 회차 상태·차감 규칙은 [README](../README.md#회차-상태와-차감-규칙)를 기준으로 합니다.

## 공통 사항

- **액터:** 강사 (로그인한 프리랜서 강사). MVP에는 다른 액터가 없습니다.
- **데이터 소유:** 강사는 **자기가 등록한 데이터만** 보고 수정할 수 있습니다. (모든 유스케이스 공통 수용 기준)
- **용어**

| 용어 | 뜻 | 모델(가칭) |
|---|---|---|
| 수강생 | 강사에게 레슨을 받는 사람 | `Student` |
| 레슨권 | 수강생이 등록한 레슨 묶음 (예: 피아노 8회) | `Enrollment` |
| 회차 | 특정 날짜·시간에 열리는 수업 1회 | `LessonSession` (Django 내장 `Session`과 구분) |
| 장소 메모 | 회차마다 자유롭게 적는 장소 (예: A 레슨실) | `LessonSession.place` |
| 수업일지 | 회차별 진도·메모 | `LessonRecord` |
| 라벨 | 레슨권을 색으로 구분하는 이름표 (예: 피아노, 출강) | `Label` |

## MVP

### UC-01 강사 회원가입·로그인

- **목표:** 강사가 계정을 만들고 로그인해 자기 데이터에 접근한다.
- **사전조건:** 없음
- **기본 흐름**
  1. 강사가 이메일(아이디)·비밀번호·이름을 입력해 가입한다.
  2. 강사가 로그인한다.
  3. 시스템이 강사의 홈(오늘 일정)으로 이동한다.
- **대안 흐름**
  - 이미 가입된 이메일 → 오류 메시지 표시
  - 비밀번호 오류 → 로그인 실패 메시지 표시
- **MVP 제외:** 이메일 인증, 소셜 로그인. 비밀번호 찾기·변경은 UC-15에서 다룬다.
- **수용 기준**
  - [ ] 회원가입·로그인·로그아웃이 동작한다.
  - [ ] 로그인하지 않은 사용자는 로그인 화면 외 페이지에 접근할 수 없다.
  - [ ] 비밀번호는 Django 기본 해시로 저장된다.

### UC-02 수강생 등록·수정

- **목표:** 강사가 레슨 상대를 등록하고 관리한다.
- **사전조건:** 로그인 상태
- **기본 흐름**
  1. 강사가 "수강생 추가"를 누른다.
  2. 이름(필수), 연락처·메모(선택), 미성년자 여부를 입력한다.
  3. 미성년자로 체크하면 보호자 연락처(필수)와 보호자 이름(선택)을 입력한다.
  4. 시스템이 저장하고 수강생 목록에 표시한다.
- **대안 흐름**
  - 이름 누락 → 입력 오류 표시
  - 미성년자인데 보호자 연락처 누락 → 입력 오류 표시
  - 수강생 정보 수정
  - 수강 종료(보관) 처리 → 남은 `예정` 회차가 있으면 "예정 회차 N개가 삭제됩니다"를 확인받은 뒤 삭제하고 보관. 완료·휴강·결석 기록은 그대로 남는다.
- **수용 기준**
  - [ ] 수강생을 등록·수정할 수 있다.
  - [ ] 수강생 목록에 이름과 잔여 회차(UC-07)가 보인다.
  - [ ] 다른 강사의 수강생은 보이지 않는다.
  - [ ] 보관한 수강생은 목록과 일정 조회에서 기본으로 숨겨지고, 남은 예정 회차는 삭제된다.
  - [ ] 미성년자 수강생은 보호자 연락처 없이 저장되지 않는다.
  - [ ] 개인정보는 필요한 최소 항목만 받는다. (생년월일 대신 미성년자 여부만)

### UC-03 레슨권 등록

- **목표:** 수강생이 몇 회 레슨을 등록했는지 기록한다.
- **사전조건:** 수강생이 등록되어 있음
- **기본 흐름**
  1. 강사가 수강생 상세에서 "레슨권 추가"를 누른다.
  2. 레슨명(예: 피아노 개인 레슨), 총 회차(예: 8), 시작일, 라벨(선택, UC-16)을 입력한다.
  3. 시스템이 저장하고 잔여 회차를 총 회차로 표시한다.
- **대안 흐름**
  - 총 회차가 1 미만 → 입력 오류
  - 기존 레슨권을 다 쓴 뒤 새 레슨권 추가 → 시스템이 소진된 이전 레슨권의 종료를 제안하고, 강사가 확인하면 종료 상태로 보관
  - 레슨권 종료는 강사가 직접 한다. 잔여 0이 되어도 자동 종료하지 않는다.
- **수용 기준**
  - [ ] 수강생에게 레슨권을 등록할 수 있다.
  - [ ] 한 수강생이 여러 레슨권을 가질 수 있고, 진행 중인 레슨권이 구분된다.

### UC-04 레슨 회차(일정) 등록

- **목표:** 레슨권에 속한 수업 1회의 날짜·시간을 등록한다.
- **사전조건:** 진행 중인 레슨권이 있음
- **기본 흐름**
  1. 강사가 "일정 추가"에서 수강생(레슨권)을 고른다.
  2. 날짜, 시작·종료 시간, 장소 메모(선택, 자유 입력 예: A 레슨실)를 입력한다.
  3. 시스템이 `예정` 상태의 회차로 저장한다.
- **대안 흐름**
  - 종료 시간이 시작 시간보다 이르면 입력 오류
  - 같은 시간에 강사의 다른 회차가 있으면 겹침 경고 (저장은 허용)
  - 저장 후 기준으로 이 레슨권의 `예정` 회차 수(지금 저장하는 회차 포함, 수정이면 한 번만 셈)가 잔여 회차를 **초과(>)**하면 "잔여 회차를 넘는 일정" 경고 (저장은 허용). 예: 잔여 3회·예정 3회는 경고 없음, 예정 4회째부터 경고
- **수용 기준**
  - [ ] 회차를 등록·수정·삭제할 수 있다. (삭제는 `예정` 상태만)
  - [ ] 새 회차의 상태는 `예정`이다.
  - [ ] 시간 겹침 시 경고가 표시된다.
  - [ ] 잔여 회차를 넘는 일정을 등록하면 경고가 표시된다.

### UC-05 일정 조회

- **목표:** 서로 다른 수강생의 레슨 일정을 한눈에 본다.
- **사전조건:** 로그인 상태
- **기본 흐름**
  1. 강사가 홈 또는 일정 화면에 들어간다.
  2. 시스템이 이번 달 달력을 보여주고, 회차가 있는 날에 점을 표시한다. 오늘이 선택되어 오늘 회차가 달력 아래에 시간순으로 보인다. (수강생명, 시간, 장소 메모, 상태)
  3. 강사가 날짜를 눌러 그날 회차를 보거나, 이전·다음 달로 이동한다.
  4. 필요하면 주간 보기로 바꿔 한 주의 회차를 날짜별로 본다.
- **대안 흐름**
  - 일정이 없는 날 → "일정 없음" 표시
  - 수강생별·라벨별 필터 (UC-16)
- **수용 기준**
  - [ ] 월간 달력에서 회차가 있는 날이 표시되고, 날짜를 누르면 그날 회차 목록이 보인다.
  - [ ] 월간·주간 보기를 전환할 수 있고 이전·다음 달(주)로 이동할 수 있다.
  - [ ] 각 회차의 상태(예정/완료/휴강/결석)가 구분되고, 보강 회차는 `보강` 표시로 따로 구분된다.
  - [ ] 회차를 누르면 상세(완료 처리 등)로 이동한다.

### UC-06 수업 완료 처리

- **목표:** 예정된 수업이 실제로 진행되었음을 기록한다.
- **사전조건:** `예정` 상태의 회차가 있음
- **기본 흐름**
  1. 강사가 회차에서 "완료"를 누른다.
  2. 시스템이 상태를 `완료`로 바꾸고 레슨권 회차를 1회 차감한다.
  3. 화면에 갱신된 진행·잔여 회차가 보인다.
- **대안 흐름**
  - 잘못 누른 경우 "완료 취소" → `예정`으로 되돌림. 단, 수업일지를 쓴 회차는 되돌릴 수 없음
  - 잔여 회차가 0인 레슨권 → 완료는 허용하되 "회차 초과" 경고
  - 시작 시각 전인 회차 → 완료는 허용하되 "아직 시작 전인 수업입니다" 확인을 받음
- **수용 기준**
  - [ ] 완료 처리 시 상태가 `완료`로 바뀐다.
  - [ ] 진행·잔여 회차가 즉시 반영된다.
  - [ ] 완료 취소 시 `예정`으로 돌아가고 잔여 회차가 복구된다. (수업일지가 있으면 불가)
  - [ ] 차감 계산에 대한 단위 테스트가 있다.

### UC-07 진행·잔여 회차 확인

- **목표:** 수강생별로 몇 회 했고 몇 회 남았는지 확인한다.
- **사전조건:** 레슨권이 등록되어 있음
- **기본 흐름**
  1. 강사가 수강생 상세에 들어간다.
  2. 시스템이 레슨권별 `총 / 진행 / 잔여` 회차와 회차 이력(날짜·상태)을 보여준다.
- **수용 기준**
  - [ ] `잔여 = 총 회차 − 차감된 회차`로 계산된다. ([회차 규칙](../README.md#회차-상태와-차감-규칙))
  - [ ] 잔여 회차가 적으면(예: 2회 이하) 목록에서 강조된다.
  - [ ] 잔여 0 이하인 레슨권은 '소진'으로 표시된다. (자동 종료하지 않음)
  - [ ] 계산 로직에 대한 단위 테스트가 있다.

### UC-15 비밀번호 찾기·변경

- **목표:** 강사가 운영자 도움 없이 비밀번호를 바꾸거나, 잊었을 때 스스로 재설정한다.
- **사전조건:** 가입된 강사 계정 (변경은 로그인 상태)
- **기본 흐름 (비밀번호 찾기)**
  1. 강사가 로그인 화면에서 "비밀번호 찾기"를 누르고 가입 이메일을 입력한다.
  2. 시스템이 재설정 링크를 메일로 보낸다. 화면에는 가입 여부와 관계없이 같은 안내를 보여준다.
  3. 강사가 메일의 링크를 열어 새 비밀번호를 두 번 입력한다.
  4. 시스템이 비밀번호를 바꾸고 로그인 화면으로 안내한다.
- **기본 흐름 (비밀번호 변경)**
  1. 로그인한 강사가 "비밀번호 변경"에서 현재 비밀번호와 새 비밀번호를 입력한다.
  2. 시스템이 비밀번호를 바꾼다.
- **대안 흐름**
  - 링크가 만료(1시간)되었거나 이미 사용됨 → "링크가 유효하지 않습니다" 안내 후 다시 요청
  - 메일 발송이 안 되는 경우 → 비상용으로 운영자가 관리자 화면(`/admin/`)에서 재설정
- **수용 기준**
  - [ ] Django 기본 재설정 기능(`PasswordResetView` 등)으로 구현한다.
  - [ ] 재설정 링크는 1회용이며 1시간 뒤 만료된다. (`PASSWORD_RESET_TIMEOUT = 3600`)
  - [ ] 없는 이메일을 입력해도 가입 여부가 드러나지 않는다.
  - [ ] 개발 환경은 메일을 콘솔에 출력하고, 배포 환경은 Gmail SMTP(앱 비밀번호)로 발송한다.
  - [ ] 메일 계정 정보는 `.env`에만 두고 커밋하지 않는다.
  - [ ] 로그인한 강사가 비밀번호를 변경할 수 있다.

### UC-16 라벨 관리 (수업 형태·사람 구분 색)

- **목표:** 강사가 수업 형태나 사람에 따라 라벨(이름 + 색)을 만들어, 달력과 목록에서 한눈에 구분한다.
- **사전조건:** 로그인 상태
- **기본 흐름**
  1. 강사가 계정 메뉴의 "라벨"(S12)에서 "추가"를 누른다.
  2. 이름(예: 피아노, 출강, 체험, 또는 수강생 이름)과 색(정해진 8색 중 하나)을 고른다.
  3. 레슨권 등록·수정(UC-03) 때 라벨을 고른다. 레슨권 폼에서 "+ 새 라벨"로 바로 만들 수도 있다.
  4. 일정 조회(UC-05)에서 그 레슨권의 회차가 라벨 색(목록 색 막대, 달력 점)으로 표시된다.
- **대안 흐름**
  - 같은 이름의 라벨이 이미 있음 → 입력 오류
  - 라벨 삭제 → "레슨권 N개가 라벨 없음이 됩니다" 확인 후 삭제. 해당 레슨권은 회색으로 표시되고 회차 기록은 그대로
  - 일정 조회에서 라벨별로 걸러 보기
- **수용 기준**
  - [ ] 라벨을 추가·수정·삭제할 수 있고, 색은 8색 중에서만 고를 수 있다.
  - [ ] 레슨권에 라벨을 하나 붙이거나 비울 수 있다.
  - [ ] 월간 달력의 점과 회차 목록의 색 막대가 라벨 색으로 보이고, 라벨이 없으면 회색이다.
  - [ ] 회차 상태는 색이 아니라 모양(체크·흐리게·취소선)으로 표시되어 라벨 색과 섞이지 않는다.
  - [ ] 다른 강사의 라벨은 보이지 않고, 같은 강사 안에서 라벨 이름은 중복되지 않는다.

## 확장

### UC-08 휴강 처리

- **목표:** 강사 사유로 열리지 않은 수업을 기록한다.
- **사전조건:** `예정` 상태의 회차
- **기본 흐름**
  1. 강사가 회차에서 "휴강"을 누르고 사유(선택)를 입력한다.
  2. 시스템이 상태를 `휴강`으로 바꾼다. 레슨권은 차감하지 않는다.
  3. 시스템이 "보강 일정 등록"(UC-09)을 안내한다.
- **수용 기준**
  - [ ] 휴강 회차는 잔여 회차에 영향을 주지 않는다.
  - [ ] 보강이 아직 없는 휴강 회차에는 "보강 필요" 배지가 붙고, 수강생 상세에서 따로 모아 볼 수 있다.

### UC-09 보강 일정 등록

- **목표:** 휴강·결석한 수업을 대체하는 회차를 만든다.
- **사전조건:** `휴강` 또는 **미차감** `결석` 상태의 회차 (차감한 결석은 보강 불가)
- **기본 흐름**
  1. 강사가 휴강 회차에서 "보강 등록"을 누른다.
  2. 날짜·시간·장소 메모를 입력한다.
  3. 시스템이 원래 회차와 연결된 보강 회차를 `예정` 상태로 만든다. (보강은 상태가 아니라 연결)
  4. 보강 회차를 완료 처리하면 1회 차감된다.
- **수용 기준**
  - [ ] 보강 회차와 원래 회차가 서로 연결되어 보인다.
  - [ ] 한 휴강 회차에 보강은 하나만 연결된다.
  - [ ] 차감한 결석에는 보강을 등록할 수 없다. (중복 차감 방지)
  - [ ] 보강 회차 완료 시 1회만 차감된다.

### UC-10 결석 처리

- **목표:** 학생 사유로 불참한 수업을 기록한다.
- **사전조건:** `예정` 상태의 회차
- **기본 흐름**
  1. 강사가 회차에서 "결석"을 누른다.
  2. 강사가 차감 여부를 선택한다. 기본값이 없어 반드시 골라야 한다.
  3. 시스템이 상태를 `결석`으로 바꾸고 선택에 따라 차감한다.
- **수용 기준**
  - [ ] 차감 여부를 고르지 않으면 저장되지 않는다.
  - [ ] 차감·미차감 결석이 잔여 회차에 맞게 반영된다.
  - [ ] 미차감 결석은 보강 등록(UC-09)으로 이어질 수 있다.

### UC-11 회차 일정 변경

- **목표:** 이미 잡힌 수업의 날짜·시간·장소를 바꾼다.
- **사전조건:** `예정` 상태의 회차
- **기본 흐름**
  1. 강사가 회차를 열고 날짜·시간·장소 메모를 수정한다.
  2. 시스템이 저장하고 변경 이력(이전 일시)을 남긴다.
- **수용 기준**
  - [ ] 변경 후 일정 조회에 새 일시로 표시된다.
  - [ ] 변경 전 일시를 확인할 수 있다.

### UC-12 반복 일정 등록

- **목표:** 정기 레슨(예: 매주 화·목 17시)을 한 번에 등록한다.
- **사전조건:** 진행 중인 레슨권
- **기본 흐름**
  1. 강사가 요일·시간·시작일과 횟수(또는 종료일)를 입력한다.
  2. 시스템이 해당 회차들을 미리 보여준다.
  3. 강사가 확인하면 `예정` 회차들을 한꺼번에 만든다.
- **대안 흐름**
  - 기존 `예정` 회차 수 + 생성할 회차 수가 잔여 회차를 초과(>)하면 경고 (UC-04와 같은 기준)
- **수용 기준**
  - [ ] 반복 규칙대로 회차가 생성된다.
  - [ ] 생성된 회차를 개별 수정·휴강 처리할 수 있다.

### UC-13 장소 지도 연동 (프로젝트 이후)

- **목표:** 자주 쓰는 장소를 주소·지도와 함께 등록해 수업 장소와 이동 동선을 확인한다.
- **현재 범위:** 프로젝트 기간에는 회차별 장소 메모(UC-04)만 제공한다. 이 유스케이스는 프로젝트 기간이 끝난 뒤 진행한다.
- **기본 흐름 (안)**
  1. 강사가 장소명·기관명·주소를 등록하고 지도에서 위치를 확인한다.
  2. 회차 등록 시 등록된 장소를 고르거나 메모로 적는다.
  3. 일정 조회에서 장소를 지도로 보고 장소별로 필터한다.
- **수용 기준 (안)**
  - [ ] 장소를 등록·수정할 수 있고 지도에 표시된다.
  - [ ] 기존 회차의 장소 메모를 등록된 장소로 옮길 수 있다.
  - [ ] 일정 조회에서 장소별로 필터된다.
- 지도 API(카카오맵·네이버 지도 등)는 착수할 때 결정한다.

### UC-14 수업일지 작성

- **목표:** 회차별 진도와 메모를 일정과 연결해 남긴다.
- **사전조건:** `완료` 상태의 회차 (보강 회차 포함)
- **기본 흐름**
  1. 강사가 완료된 회차에서 "수업일지"를 연다.
  2. 진도·내용·과제·메모를 입력한다.
  3. 수강생 상세에서 회차별 일지를 시간순으로 본다.
- **수용 기준**
  - [ ] 회차마다 수업일지를 작성·수정할 수 있다.
  - [ ] 수강생 상세에서 일지 이력을 볼 수 있다.
