# LEMIT 유스케이스

> 기능별 사용 시나리오와 완료 기준을 정리한 문서입니다. 각 유스케이스는 GitHub 이슈 하나와 1:1로 연결됩니다.
> 기획 배경은 [PROJECT_PLAN.md](PROJECT_PLAN.md), 회차 상태·차감 규칙은 [README](../README.md#회차-상태와-차감-규칙)를 기준으로 합니다.

## 공통 사항

- **액터:** 강사 (로그인한 프리랜서 강사). MVP에는 다른 액터가 없습니다. 수강생 메시지(UC-17)도 MVP에서는 강사가 시연용으로 대신 등록합니다.
- **데이터 소유:** 강사는 **자기가 등록한 데이터만** 보고 수정할 수 있습니다. (모든 유스케이스 공통 수용 기준)
- **용어**

| 용어 | 뜻 | 모델(가칭) |
|---|---|---|
| 수강생 | 강사에게 레슨을 받는 사람 | `Student` |
| 레슨권 | 수강생이 등록한 레슨 묶음 (예: 피아노 8회) | `Enrollment` |
| 회차 | 특정 날짜·시간에 열리는 수업 1회 | `LessonSession` (Django 내장 `Session`과 구분) |
| 장소 메모 | 회차마다 자유롭게 적는 장소 (예: A 레슨실) | `LessonSession.place` |
| 수업일지 | 회차별 진도·메모 | `LessonRecord` |
| 라벨 | 레슨권을 색으로 구분하는 이름표 (예: 피아노, 출강) | `Label` |
| 대화 | 강사와 수강생 한 명이 주고받는 메시지 묶음 (메일 스레드) | `Conversation` |
| 메시지 | 대화 안의 메시지 1건. 수강생 메시지는 AI 분류 결과를 함께 저장 | `Message` |
| AI 분류 | 직접 학습시킨 모델이 수강생 메시지를 휴강 요청·보강 요청·일정 변경·일반 메시지로 예측한 결과. 참고용 | `Message.predicted_label` |

## MVP

### UC-01 강사 회원가입·로그인

- **목표:** 강사가 계정을 만들고 로그인해 자기 데이터에 접근한다.
- **사전조건:** 없음
- **기본 흐름**
  1. 강사가 이메일(아이디)·비밀번호·이름을 입력해 가입한다.
  2. 강사가 로그인한다.
  3. 시스템이 강사의 홈(오늘 일정)으로 이동한다.
- **대안 흐름**
  - 이미 가입된 이메일 → 오류 메시지 표시
  - 비밀번호 오류 → 로그인 실패 메시지 표시
- **MVP 제외:** 이메일 인증, 소셜 로그인. 비밀번호 찾기·변경은 UC-15에서 다룬다.
- **수용 기준**
  - [x] 회원가입·로그인·로그아웃이 동작한다. (테스트, 2026-11-19)
  - [x] 로그인하지 않은 사용자는 공개 화면(로그인·회원가입·비밀번호 재설정)을 제외한 서비스 화면에 접근할 수 없고, 로그인 화면으로 이동한다. ([SCREENS.md 접근 정책](SCREENS.md)) (모든 URL 대상 테스트)
  - [x] 비밀번호는 Django 기본 해시로 저장된다. (테스트)
  - [x] 이메일은 대소문자를 구분하지 않는다: 같은 이메일로 두 번 가입할 수 없고, 대소문자가 달라도 로그인된다. (2026-11-19 추가)
  - [x] 로그인 실패 메시지는 비밀번호 오류와 미가입 이메일이 같다 (가입 여부 비노출). (2026-11-19 추가)
- **참고:** 로그인 후 홈은 대시보드(S00, #45)입니다. 월간 일정(S05)은 사이드바 '수업 일정' 화면으로 UC-05에서 만듭니다.

### UC-02 수강생 등록·수정

- **목표:** 강사가 레슨 상대를 등록하고 관리한다.
- **사전조건:** 로그인 상태
- **기본 흐름**
  1. 강사가 "수강생 추가"를 누른다.
  2. 이름(필수), 연락처·메모(선택), 미성년자 여부를 입력한다.
  3. 미성년자로 체크하면 보호자 연락처(필수)와 보호자 이름(선택)을 입력한다.
  4. 시스템이 저장하고 수강생 목록에 표시한다.
- **대안 흐름**
  - 이름 누락 → 입력 오류 표시
  - 미성년자인데 보호자 연락처 누락 → 입력 오류 표시
  - 수강생 정보 수정
  - 수강 종료(보관) 처리 → 남은 `예정` 회차가 있으면 "예정 회차 N개가 삭제됩니다"를 확인받은 뒤 삭제하고 보관. 완료·휴강·결석 기록은 그대로 남는다.
- **수용 기준**
  - [x] 수강생을 등록·수정할 수 있다. (테스트, 2026-11-19)
  - [x] 수강생 목록에 이름과 잔여 회차(UC-07)가 보인다. (진행 중 레슨권별 잔여, 2026-11-20 UC-07)
  - [x] 다른 강사의 수강생은 보이지 않는다. 상세·수정·보관 주소로 직접 접근하면 404, 조작된 POST로도 바꿀 수 없다. (강사 A/B 격리 테스트)
  - [x] 보관한 수강생은 목록과 일정 조회에서 기본으로 숨겨지고, 남은 예정 회차는 삭제된다. (목록 숨김 PR #37, 예정 회차 삭제를 보관과 한 트랜잭션으로 PR #59, 일정 조회 숨김 PR #61, 2026-11-20). 보관 해제는 '수강 중' 상태만 되돌리고 지운 예정 회차는 되살리지 않는다(필요하면 다시 등록)
  - [x] 미성년자 수강생은 보호자 연락처 없이 저장되지 않는다. (폼 + DB 제약)
  - [x] 개인정보는 필요한 최소 항목만 받는다. (생년월일 대신 미성년자 여부만, 미성년자가 아니면 보호자 정보 저장 안 함)

### UC-03 레슨권 등록

- **목표:** 수강생이 몇 회 레슨을 등록했는지 기록한다.
- **사전조건:** 수강생이 등록되어 있음
- **기본 흐름**
  1. 강사가 수강생 상세에서 "레슨권 추가"를 누른다.
  2. 레슨명(예: 피아노 개인 레슨), 총 회차(예: 8), 시작일, 라벨(선택, UC-16)을 입력한다.
  3. 시스템이 저장하고 잔여 회차를 총 회차로 표시한다.
- **대안 흐름**
  - 총 회차가 1 미만 → 입력 오류
  - 기존 레슨권을 다 쓴 뒤 새 레슨권 추가 → 시스템이 소진된 이전 레슨권의 종료를 제안하고, 강사가 확인하면 종료 상태로 보관
  - 레슨권 종료는 강사가 직접 한다. 잔여 0이 되어도 자동 종료하지 않는다.
- **수용 기준**
  - [ ] 수강생에게 레슨권을 등록할 수 있다.
  - [ ] 한 수강생이 여러 레슨권을 가질 수 있고, 진행 중인 레슨권이 구분된다.
  - [x] 이전 레슨권이 있는 수강생에게 추가할 때는 이전 레슨명(최근 것부터, 중복 없이 최대 5개)을 고를 수 있고 가장 최근 레슨명이 기본 선택이다. '직접 입력'을 고르면 새 이름을 입력해 저장하고, 이전 레슨권이 없으면 바로 입력한다. (#75, 2026-11-23, 테스트 `lessons/test_enrollment_title.py`)

### UC-04 레슨 회차(일정) 등록

- **목표:** 레슨권에 속한 수업 1회의 날짜·시간을 등록한다.
- **사전조건:** 진행 중인 레슨권이 있음
- **기본 흐름**
  1. 강사가 "일정 추가"에서 수강생(레슨권)을 고른다.
  2. 날짜, 시작·종료 시간, 장소 메모(선택, 자유 입력 예: A 레슨실)를 입력한다.
  3. 시스템이 `예정` 상태의 회차로 저장한다.
- **대안 흐름**
  - 종료 시간이 시작 시간보다 이르면 입력 오류
  - 같은 시간에 강사의 다른 회차가 있으면 겹침 경고 (저장은 허용)
  - 저장 후 기준으로 이 레슨권의 `예정` 회차 수(지금 저장하는 회차 포함, 수정이면 한 번만 셈)가 잔여 회차를 **초과(>)**하면 "잔여 회차를 넘는 일정" 경고 (저장은 허용). 예: 잔여 3회·예정 3회는 경고 없음, 예정 4회째부터 경고
- **수용 기준**
  - [ ] 회차를 등록·수정·삭제할 수 있다. (삭제는 `예정` 상태만)
  - [ ] 새 회차의 상태는 `예정`이다.
  - [ ] 시간 겹침·잔여 초과는 저장을 막지 않고, 한 번에 저장한 뒤 다음 화면 알림으로 경고한다. (두 번 확인하는 단계 없음)
  - [ ] 저장 후 리다이렉트해서 새로고침으로 같은 회차가 중복 생성되지 않는다.
  - [ ] 다른 강사의 레슨권으로 회차를 만들 수 없다 (조작된 요청 포함).

### UC-05 일정 조회

- **목표:** 서로 다른 수강생의 레슨 일정을 한눈에 본다.
- **사전조건:** 로그인 상태
- **기본 흐름**
  1. 강사가 홈 또는 일정 화면에 들어간다.
  2. 시스템이 이번 달 달력을 보여주고, 회차가 있는 날에 점을 표시한다. 오늘이 선택되어 오늘 회차가 달력 아래에 시간순으로 보인다. (수강생명, 시간, 장소 메모, 상태)
  3. 강사가 날짜를 눌러 그날 회차를 보거나, 이전·다음 달로 이동한다.
  4. 필요하면 주간 보기로 바꿔 한 주의 회차를 날짜별로 본다.
- **대안 흐름**
  - 일정이 없는 날 → "일정 없음" 표시
  - 수강생별·라벨별 필터 (UC-16)
- **수용 기준**
  - [x] 월간 달력에서 회차가 있는 날이 표시되고, 날짜를 누르면 그날 회차 목록이 보인다. (2026-11-20)
  - [x] 월간·주간 보기를 전환할 수 있고 이전·다음 달(주)로 이동할 수 있다. (2026-11-20)
  - [x] 각 회차의 상태(예정/완료/휴강/결석)가 구분되고, 보강 회차는 `보강` 표시로 따로 구분된다. (모양으로 구분, 2026-11-20)
  - [x] 회차를 누르면 상세(완료 처리 등)로 이동한다. (2026-11-20)

### UC-06 수업 완료 처리

- **목표:** 예정된 수업이 실제로 진행되었음을 기록한다.
- **사전조건:** `예정` 상태의 회차가 있음
- **기본 흐름**
  1. 강사가 회차에서 "완료"를 누른다.
  2. 시스템이 상태를 `완료`로 바꾸고 레슨권 회차를 1회 차감한다.
  3. 화면에 갱신된 진행·잔여 회차가 보인다.
- **대안 흐름**
  - 잘못 누른 경우 "완료 취소" → `예정`으로 되돌림. 단, 수업일지를 쓴 회차는 되돌릴 수 없음
  - 잔여 회차가 0인 레슨권 → 완료는 허용하되 "회차 초과" 경고
  - 시작 시각 전인 회차 → 완료는 허용하되 "아직 시작 전인 수업입니다" 확인을 받음
- **수용 기준**
  - [ ] 완료 처리 시 상태가 `완료`로 바뀐다.
  - [ ] 진행·잔여 회차가 즉시 반영된다.
  - [ ] 완료 취소 시 `예정`으로 돌아가고 잔여 회차가 복구된다. (수업일지가 있으면 불가)
  - [ ] 차감 계산에 대한 단위 테스트가 있다.

### UC-07 진행·잔여 회차 확인

- **목표:** 수강생별로 몇 회 했고 몇 회 남았는지 확인한다.
- **사전조건:** 레슨권이 등록되어 있음
- **기본 흐름**
  1. 강사가 수강생 상세에 들어간다.
  2. 시스템이 레슨권별 `총 / 진행 / 잔여` 회차와 회차 이력(날짜·상태)을 보여준다.
- **수용 기준**
  - [x] `잔여 = 총 회차 − 차감된 회차`로 계산된다. ([회차 규칙](../README.md#회차-상태와-차감-규칙)) (레슨권별 서브쿼리 집계)
  - [x] 잔여 회차가 적으면(예: 2회 이하) 목록에서 강조된다. (수강생 목록·레슨권 카드, 글자·아이콘으로도 표시)
  - [x] 잔여 0 이하인 레슨권은 '소진'으로 표시된다. (자동 종료하지 않음, 초과 진행이면 '초과 N회')
  - [x] 계산 로직에 대한 단위 테스트가 있다. (경계값 3·2·1·0·−1, 회차 조건 조인, 목록 쿼리 수 고정)

### UC-15 비밀번호 찾기·변경

  - [x] 변경 후 일정 조회에 새 일시로 표시된다. (예정 회차 '수정'으로 날짜·시간·장소 변경, 주간 보기에서 새 주에만 표시, `lessons/test_reschedule.py`)
  - [x] 변경 전 일시를 확인할 수 있다. (회차 상세 '일정 변경 이력'에 변경 전·후와 변경 시각을 최신순으로. 레슨권만 옮긴 수정은 남기지 않음, 장소만 바뀐 경우 구분)

### UC-12 반복 일정 등록

- **목표:** 정기 레슨(예: 매주 화·목 17시)을 한 번에 등록한다.
- **사전조건:** 진행 중인 레슨권
- **기본 흐름**
  1. 강사가 요일·시간·시작일과 횟수(또는 종료일)를 입력한다.
  2. 시스템이 해당 회차들을 미리 보여준다.
  3. 강사가 확인하면 `예정` 회차들을 한꺼번에 만든다.
- **대안 흐름**
  - 기존 `예정` 회차 수 + 생성할 회차 수가 잔여 회차를 초과(>)하면 경고 (UC-04와 같은 기준)
- **수용 기준**
  - [ ] 반복 규칙대로 회차가 생성된다.
  - [ ] 생성된 회차를 개별 수정·휴강 처리할 수 있다.

### UC-13 장소 지도 연동 (프로젝트 이후)

- **목표:** 자주 쓰는 장소를 주소·지도와 함께 등록해 수업 장소와 이동 동선을 확인한다.
- **현재 범위:** 프로젝트 기간에는 회차별 장소 메모(UC-04)만 제공한다. 이 유스케이스는 프로젝트 기간이 끝난 뒤 진행한다.
- **기본 흐름 (안)**
  1. 강사가 장소명·기관명·주소를 등록하고 지도에서 위치를 확인한다.
  2. 회차 등록 시 등록된 장소를 고르거나 메모로 적는다.
  3. 일정 조회에서 장소를 지도로 보고 장소별로 필터한다.
- **수용 기준 (안)**
  - [ ] 장소를 등록·수정할 수 있고 지도에 표시된다.
  - [ ] 기존 회차의 장소 메모를 등록된 장소로 옮길 수 있다.
  - [ ] 일정 조회에서 장소별로 필터된다.
- 지도 API(카카오맵·네이버 지도 등)는 착수할 때 결정한다.

### UC-14 수업일지 작성

- **목표:** 회차별 진도와 메모를 일정과 연결해 남긴다.
- **사전조건:** `완료` 상태의 회차 (보강 회차 포함)
- **기본 흐름**
  1. 강사가 완료된 회차에서 "수업일지"를 연다.
  2. 진도·내용·과제·메모를 입력한다.
  3. 수강생 상세에서 회차별 일지를 시간순으로 본다.
- **수용 기준**
  - [ ] 회차마다 수업일지를 작성·수정할 수 있다.
  - [ ] 수강생 상세에서 일지 이력을 볼 수 있다.
