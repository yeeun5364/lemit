# 레슨 메모 AI 분류 (ML 설계)

> **상태 (2026-11-19):** 모델 학습·평가·저장, Django 추론 서비스, `/healthz/`, CI 검증 **구현·테스트 통과 (PR 검토 중)**. 회차 화면의 메모 입력 UI(UC-17)는 **설계만**, Docker 이미지·Lightsail 배포 검증은 **미착수**.
> 관련 이슈: #32(모델·추론 서비스), #33(UC-17 화면), #5·#7(이미지·배포) · 학습 결과 원본: [ml/artifacts/REPORT.md](../ml/artifacts/REPORT.md) (학습 스크립트가 자동 생성)

## 1. 무엇을 하는가

강사가 회차에 적는 메모(학생·학부모 연락 내용, 강사 메모)를 직접 학습시킨 모델이 네 가지 중 하나로 분류해 **배지로 보여줍니다.**

| 분류 | 화면 표시 | 기준 (라벨링 가이드) |
|---|---|---|
| `CANCELLATION` | 휴강 요청 | 수업을 쉬겠다는 내용. 대신할 날짜·추가 수업 제안이 **없음** |
| `MAKEUP` | 보강 요청 | 빠졌거나 빠질 수업을 **다른 날 추가로** 하자는 내용. "못 가니 금요일에 보강"처럼 휴강+보강이 함께 있으면 `MAKEUP` |
| `RESCHEDULE` | 일정 변경 | **같은 회차**의 날짜·시간·장소·방식(온라인 등)을 옮기는 내용 |
| `GENERAL` | 일반 메모 | 진도, 숙제, 준비물, 결제, 칭찬·상담 등 일정 요청이 아닌 것 |

**원칙: 예측은 참고용입니다.** 예측 결과로 회차 상태나 일정을 자동으로 바꾸지 않습니다. 강사가 배지를 보고 휴강·보강·수정 버튼을 직접 누릅니다.

## 2. 기술 선택

| 항목 | 선택 | 이유 |
|---|---|---|
| 모델 | TF-IDF + Logistic Regression (scikit-learn) | 데이터가 수백 건이라 딥러닝보다 단순 선형 모델이 과적합이 적고, 학습 1초·추론 1ms 수준. CPU만으로 동작해 GPU·별도 추론 서버가 필요 없음 |
| 특징 | 글자 단위 n-gram(`char_wb`, 1~3) | 한국어는 조사·어미가 붙어 띄어쓰기 단어가 잘게 바뀜("보강", "보강해", "보강은"). 형태소 분석기(KoNLPy, Java 필요) 없이 이 문제를 줄임. 교차검증에서 단어 단위보다 macro F1이 약 0.11 높았음 |
| 저장 | joblib + 메타데이터 JSON | scikit-learn 기본 저장 방식. 버전·해시·점수를 JSON에 함께 기록해 불러올 때 확인 |
| 서비스 구조 | Django 모놀리스 안에서 직접 추론 | 모델 파일 60KB, 추론이 가벼워 FastAPI 등 별도 서버를 두면 배포·장애 지점만 늘어남 (기획서 §7 모놀리스 원칙) |
| 외부 AI API | 사용 안 함 | 과제 조건이 "직접 학습한 모델"이고, 메모를 외부로 보내지 않아도 됨 |

## 3. 데이터

- **전부 직접 작성한 합성 예문**입니다. 실제 학생·학부모의 메시지나 개인정보(이름·연락처)는 쓰지 않았습니다.
- `ml/data/memos.csv`: 학습·검증용 296건 (휴강 80, 보강 74, 일정 변경 69, 일반 73)
- `ml/data/unseen.csv`: 확인용 48건 (분류별 12). 표현을 바꿔 따로 작성했고, **학습과 모델 선택에 쓰지 않습니다.** 학습 스크립트가 두 파일의 문장이 겹치지 않는지 확인합니다.
- 요청서의 예시 문장("다음 주 수요일 수업을 못 갈 것 같아서 금요일에 보강하고 싶어요")은 학습 데이터에 들어 있으므로, 이 문장이 맞게 나오는 것은 성능 근거가 아닙니다.

## 4. 학습과 평가 절차 (`python -m ml.train --version v1`)

1. 데이터 확인: 분류 이름, 빈 문장, 중복, 확인용과 겹침, 클래스별 개수
2. 학습 80% / 검증 20% 층화 분리 (시드 42)
3. 학습 80% 안에서 5겹 교차검증으로 후보 8개 비교 (글자/단어 단위, n-gram 범위, 규제 C). **TF-IDF는 Pipeline 안에 있어 접힘마다 학습 부분에만 맞춰집니다** (검증 데이터 누수 없음)
4. 고른 모델로 검증 20%와 확인용 48건 평가: 정확도, 정밀도, 재현율, F1, 혼동행렬, 오분류 목록
5. **성능 기준(미리 정함): 검증 macro F1 ≥ 0.80, 확인용 macro F1 ≥ 0.70.** 넘을 때만 저장
6. 저장: `ml/artifacts/memo_classifier.joblib`(모델+전처리 Pipeline), `memo_classifier.json`(버전, 학습 시각, Python·scikit-learn·numpy 버전, 모델 해시, 데이터 해시, 점수, 검증 문장), `REPORT.md`

저장하는 모델은 학습 80%로만 학습한 것입니다. 전체로 다시 학습하면 조금 더 나아질 수 있지만, 그러면 기록된 검증 점수가 저장된 모델의 점수가 아니게 되고 CI에서 재현할 수 없어서 이렇게 정했습니다.

### 오분류 사례와 한계

| 문장 | 정답 | 예측 | 원인 추정 |
|---|---|---|---|
| 한 주 휴강 부탁드려요 | 휴강 | 보강 | "휴강"이 보강 예문("휴강분 보강")에 자주 함께 나와 단어가 겹침 |
| 조카 돌잔치라 토요일엔 수업 어려워요 | 휴강 | 일정 변경 | "못/쉬/취소" 같은 대표 표현 없이 돌려 말함 |
| 내일은 2시 대신 4시에 만나요 | 일정 변경 | 보강 | "대신"이 보강 예문에 많음. 숫자 시간 표현을 잘 못 씀 |
| 다음 수업은 줌으로 할게요 | 일정 변경 | 휴강 | "줌"이 학습 데이터에 없음 (온라인 전환 예문 부족) |
| 비 때문에 취소된 야외 수업은 다음 주에 보강합니다 | 보강 | 휴강 | 휴강+보강이 섞인 문장 |

- **데이터가 적습니다 (296건, 한 사람이 작성).** 점수는 "비슷한 말투의 짧은 문장"에서의 성능이며, 실제 학부모 메시지(긴 문장, 오타, 이모티콘, 여러 요청이 섞인 메시지)에서는 더 낮을 것으로 예상합니다. 실제 데이터로 검증하지 못했습니다.
- 확인용 오분류를 본 뒤에 데이터를 고치면 확인용 점수가 더는 "새 문장" 점수가 아니게 되므로, v1에서는 고치지 않았습니다. 데이터를 보강할 때는 확인용 문장도 새로 작성합니다.
- 모델은 핵심 단어("보강", "취소", "옮기")에 크게 의존합니다. 돌려 말하는 표현, 부정문("보강은 안 해도 돼요")에 약합니다.
- 화면에서는 가장 높은 확률이 0.5 미만이면 "확신 낮음"을 함께 표시해, 강사가 결과를 그대로 믿지 않도록 합니다.

## 5. 웹서비스 연동

### 구현됨 (테스트 통과)

- `memos/classifier.py`
  - `classify(text)`: 예측 결과(분류, 확신도, 모델 버전)를 돌려줌
  - 빈 메모는 `ValueError`, 500자를 넘으면 앞 500자만 사용
  - 모델 문제는 `MemoClassifierUnavailable`
  - 모델은 프로세스당 한 번만 불러와 재사용합니다. 실패는 캐시하지 않으므로, 파일을 고치면 재시작 없이 다음 요청부터 동작합니다.
- `ml/artifact.py`의 `load()`가 불러올 때 다음을 확인하고, 하나라도 어긋나면 사용하지 않습니다.
  - 파일 존재
  - SHA-256 해시
  - scikit-learn 버전
  - 분류 목록
- `/healthz/` (GET, 로그인 불필요)
  - DB 연결 실패면 503
  - 모델을 쓸 수 없으면 200을 돌려주되 `memo_classifier.status`를 `unavailable`로 표시합니다. 모델은 부가 기능이라, 없어도 일정 관리 기능은 계속 동작해야 하기 때문입니다.

### 설계 (UC-17, 회차 기능 구현 후 진행)

- **모델 `SessionMemo`:** `session`(FK, CASCADE), `text`(최대 500자), `predicted_label`, `confidence`, `model_version`, `created_at`
  - 예측 필드는 모두 비워둘 수 있습니다. 모델을 쓸 수 없을 때도 메모는 저장되어야 하기 때문입니다.
  - 상세는 문서 PR에서 [ERD.md](ERD.md)에 추가합니다.
- **화면 S06 회차 상세 아래 "메모" 영역:**
  1. 입력칸에 메모를 쓰고 저장합니다.
  2. 서버가 분류합니다.
  3. 리다이렉트(PRG)한 뒤 메모 목록에 배지를 표시합니다. 예: `보강 요청 · 82%`
- **분류가 실패하면** 메모는 저장하고 배지 자리에 "분류 불가"를 표시합니다. 회차 화면과 다른 기능에는 영향이 없습니다.
- **권한:** 회차를 로그인한 강사 기준 쿼리셋에서 찾습니다(`session__enrollment__student__teacher=request.user`). 다른 강사의 회차에 메모를 쓰거나 볼 수 없고, A/B 격리 테스트를 둡니다.
- 일정은 자동으로 바꾸지 않습니다. 배지 옆에 해당 동작 버튼(완료·수정 등, 휴강·보강은 후속 기능)만 그대로 둡니다.

## 6. 테스트·CI·배포

| 항목 | 상태 | 방법 |
|---|---|---|
| 추론 단위 테스트 | ✅ 통과 | `memos/tests.py`: 분류 결과, 확인용 문장 전체 정확도, 빈 입력, 긴 입력, 한 번만 로드, 예측 중 예외 |
| 파일 누락·손상 | ✅ 통과 | 모델/메타 파일 없음, 해시 불일치, 깨진 pickle, scikit-learn 버전 불일치, 분류 목록 불일치, 고친 뒤 자동 복구 |
| 모델·코드 호환성 | ✅ 통과 (로컬) | `python -m ml.verify`: 불러오기 검사 + 데이터 해시 일치 + 기록된 점수 재현 + 성능 기준. CI의 테스트 작업에 단계로 추가 |
| `/healthz/` | ✅ 통과 | 정상 200, 모델 없음 200+unavailable, DB 오류 503, POST 405 |
| Docker 이미지 안에서 추론 | ⬜ #5 | Dockerfile에서 `ml/artifacts/`를 이미지에 복사. 이미지 빌드 후 컨테이너에서 `python -m ml.verify` 실행 |
| 배포 후 스모크 테스트 | ⬜ #7 | `curl /healthz/`로 `status=ok`, `memo_classifier.status=ok` 확인 |
| 롤백 | ⬜ #7 | 이미지를 git 커밋 해시 태그로 저장하고, 서버는 `IMAGE_TAG`로 실행. 스모크 테스트가 실패하면 직전 태그로 다시 실행 |

- **학습과 추론 분리:** 학습은 개발 PC에서만 합니다. 서버와 CI는 저장소에 커밋된 검증된 모델을 쓰고, 다시 학습하지 않습니다.
- **모델 파일은 git에 커밋합니다** (60KB). Git LFS나 별도 저장소는 크기상 필요 없습니다.
- **라이브러리 버전 고정:** `requirements.txt`에 `scikit-learn`, `joblib`, `numpy` 버전을 고정합니다. scikit-learn 버전을 올리면 `ml.verify`가 실패하므로 다시 학습해야 합니다.
- **학습 자동화(CI에서 재학습)는 하지 않습니다.** 발표 전까지 데이터가 바뀔 일이 적고, 재학습 결과를 자동 배포하면 검토 없이 모델이 바뀌기 때문입니다.

## 7. 다시 학습하는 방법

```bash
pip install -r requirements-dev.txt
python -m ml.train --version v2     # 기준 미달이면 저장하지 않고 종료 코드 1
python -m ml.verify                 # 저장된 모델 확인
python manage.py test memos
```

모델 파일 3개(`memo_classifier.joblib`, `memo_classifier.json`, `REPORT.md`)와 데이터 변경을 같은 커밋에 넣고, 이 문서의 결과 표와 devlog를 갱신합니다.
