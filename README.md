# LEMIT (레밋)

> **Lesson + Meet** · 배움과 사람이 만나는 공간
> 수업의 모든 흐름을 하나로

**LEMIT은 프리랜서 강사가 유동적인 레슨 일정과 진행 회차를 쉽고 체계적으로 관리할 수 있도록 돕는 웹서비스입니다.**

레슨마다 시간과 장소가 다르고 휴강·보강이 자주 생기는 상황에서, 일정만 적는 일반 캘린더를 넘어 **수업 일정과 실제 진행 상태(예정/완료/휴강/보강), 진행 횟수, 수강생 기록을 하나로 연결**하는 것을 목표로 합니다.

> **현재 상태:** 기획 및 초기 설계 단계입니다. 실제 구현 여부는 아래 [구현 현황](#구현-현황)과 [devlog/](devlog/)를 기준으로 합니다.

> 📄 **상세 기획(문제 정의, 대상 사용자, 기능 우선순위, 기술 선택 이유, 아키텍처, 데이터 모델, 로드맵, 미확정 사항)은 [docs/PROJECT_PLAN.md](docs/PROJECT_PLAN.md)에서만 관리합니다.** 이 README는 요약·현황·실행 방법만 다룹니다.

## 회차 상태와 차감 규칙 (초안)

LEMIT이 일반 캘린더와 다른 핵심은 **각 수업 회차가 상태를 가지고, 그 상태에 따라 레슨권 잔여 횟수가 계산된다**는 점입니다.

> **초안입니다.** 사용자 흐름 검토 후 확정하며, 변경 시 이 표와 [devlog/](devlog/)를 함께 갱신합니다.

| 회차 상태 | 의미 | 레슨권 차감 | 후속 처리 |
|---|---|---|---|
| 예정 | 등록되었지만 아직 진행 전인 수업 | ✗ | 수업 후 완료 처리 |
| 완료 | 실제로 진행된 수업 | ✓ | 수업일지 작성(확장) |
| 휴강 | 강사 사유 등으로 열리지 않은 수업 | ✗ | 보강 회차 생성 필요 |
| 결석 | 학생 사유로 불참 (당일 취소 포함) | 강사 정책에 따름 | 차감 여부를 강사가 설정. **차감한 결석은 보강 불가** |
| 보강 | 휴강·미차감 결석을 대체하는 수업 | 완료 시 ✓ (일반 완료와 같이 1회) | 원래 회차와 연결 |

**잔여 회차 계산**

```text
잔여 회차 = 레슨권 총 회차 − 차감된 회차 수
차감된 회차 = 완료 회차 수 (보강 회차의 완료 포함) + 차감한 결석 수
```

- 보강 회차도 진행되면 `완료` 상태가 되므로 **완료 회차 수에 한 번만** 들어갑니다. 보강을 따로 더하지 않습니다.
- **중복 차감 방지:** 이미 차감한 결석에는 보강을 등록할 수 없습니다. 보강은 휴강 또는 미차감 결석에만 연결됩니다. (확정은 #2)

**상태 변경 흐름**

```text
예정 ──수업 진행──▶ 완료
  │
  ├──강사 사유──▶ 휴강 ──보강 일정 등록──▶ 보강(예정) ──진행──▶ 완료 처리(차감)
  │
  └──학생 사유──▶ 결석 ──┬─ 차감 → 종료 (보강 불가)
                        └─ 미차감 → 보강 일정 등록 가능
```

**결정이 필요한 세부 규칙**
- 결석 차감의 기본값 (예: 전날까지 취소하면 미차감, 당일 취소는 차감)
- 보강 없이 휴강만 남은 회차를 어떻게 표시할지
- 레슨권 회차를 다 쓴 뒤 추가 수업을 등록할 때의 처리 (새 레슨권 등록 등)
- 이미 완료 처리한 회차를 되돌릴 수 있는지 여부

## 실행 방법

> ⚠️ **아직 Django 프로젝트가 생성되지 않았습니다.** 아래는 구성 예정인 형태이며, 실제 구성 후 명령어를 확정합니다.

### 필요한 환경

| 구분 | 버전 | 비고 |
|---|---|---|
| Python | **3.14** | Docker 이미지 `python:3.14-slim` |
| Django | **5.2 LTS** (`>=5.2.12,<6.0`) | 보안 지원 2028년 4월까지. Python 3.14는 5.2.8부터 지원 |
| PostgreSQL | **18** | Docker 이미지 `postgres:18` (2026-11 기준 최신 18.7) |
| DB 드라이버 | psycopg 3 (`psycopg[binary]`) | |
| Docker | Engine 29 이상, Compose v2 이상 | 개발 PC 확인 버전: Docker 29.9.1, Compose v5.6.0 |
| Git | 2.x | |

- 앱과 DB는 Docker로 실행하므로 **PC에 PostgreSQL을 따로 설치할 필요가 없습니다.**
- Docker 없이 로컬에서 실행하려면 Python 3.14를 설치해야 합니다. PC에 Python 3.15가 기본으로 잡혀 있으면 `py -3.14 -m venv .venv`처럼 버전을 지정해 가상환경을 만듭니다.
- 정확한 패키지 버전은 프로젝트 생성 후 `requirements.txt`에 고정합니다.

### 환경변수 설정

```bash
cp .env.example .env
```

| 변수 | 설명 |
|---|---|
| `DJANGO_SECRET_KEY` | Django 시크릿 키 |
| `DJANGO_DEBUG` | 개발 시 `True`, 배포 시 `False` |
| `DATABASE_URL` | PostgreSQL 접속 정보 |

`.env` 파일과 비밀번호·키 값은 **절대 커밋하지 않습니다.** (`.gitignore`에 포함)

### 실행

```bash
docker compose up --build
# 최초 실행 시
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createsuperuser
```

접속: http://localhost:8000

### 테스트

```bash
docker compose exec web python manage.py test
```
