## 결정 사항
- **결석 차감:** 기본값 없음. 결석 처리 때 강사가 차감/미차감을 반드시 선택. 시간 기준 자동 규칙은 구현·설명 부담이 커서 제외
- **인증·권한 구조 (UC-01):** 인증은 미들웨어로 기본 거부, 권한은 `accounts/permissions.py`의 공통 도우미로 '로그인한 강사의 데이터로 좁힌 쿼리셋'만 사용. 다른 강사 데이터는 403 대신 404(존재 여부 비공개)
- **수강생 보관 해제 추가 (UC-02):** 명세에는 보관만 있었지만 잘못 누른 경우 관리자 화면 없이 되돌릴 수 있도록 POST 동작 하나 추가. 레슨권·잔여 회차 표시와 보관 시 예정 회차 삭제는 UC-03·UC-04에서 이 화면·동작에 붙임
- **연락처 형식 (PR #37 리뷰, 사용자 결정):** 국제번호 허용. 숫자 9~15자리(최소 `02-123-4567`, 최대 E.164 15자리), 입력한 형식 그대로 저장
- **메시지함 분류 탭 기준 (UC-17):** 대화의 '가장 최근 수강생 메시지' 분류로 거름. 강사 답장은 분류하지 않으므로 탭 기준에서 제외
- **회차 바로가기 보류:** S14의 [회차 보기]·[+ 일정 추가]와 '예측 후 회차 불변' 테스트는 회차 모델(UC-04)이 생기면 추가. 지금은 [수강생 상세]만
- **헬스체크와 스모크 테스트 역할 분리 (#5):** 컨테이너 헬스체크는 앱+DB만 봄(모델이 없어도 서비스는 살아 있어야 함). 모델 상태(`message_classifier.status == "ok"`)·ml.verify·추론 1건은 배포 스모크 테스트에서 실패로 잡음
- **정적 파일:** WhiteNoise `CompressedStaticFilesStorage`. 해시 파일명(Manifest)은 collectstatic 없이 도는 테스트를 깨뜨려 쓰지 않음. nginx 없이 시작, TLS 프록시는 #7에서 결정
- **마이그레이션은 자동 실행하지 않음:** 컨테이너 시작 때 자동으로 돌리지 않고 배포 절차에서 명시적으로 `migrate` (OPERATIONS §5 배포 순서)
- **TLS 프록시 = Caddy (#7):** 인증서 자동 발급·갱신으로 설정이 가장 짧음. compose `proxy` 프로필로 운영 서버에서만 실행. 도메인이 없으면 IP로 HTTP 시연(시연 전용 비밀번호, 실제 개인정보 금지)
- **배포는 서버에서 이미지 빌드, 태그 = 커밋 SHA:** 레지스트리 없이 시작. 이전 이미지가 서버에 남아 롤백 가능. 자동 배포(GitHub Actions)는 발표 전 제외
- **서버 OS = Amazon Linux 2023 (사용자 결정):** Docker Compose·Buildx 플러그인이 dnf 저장소에 없어 GitHub 릴리스 고정 버전(2주 이상 지난 것)을 체크섬 검증 후 설치. 스왑 2GB 추가(빌드 중 메모리 대비)
- **GitHub Actions 배포 연결은 첫 수동 배포 성공 후 (사용자 결정):** 서버에서 `scripts/deploy.sh`를 SSH로 실행하는 수동 실행(workflow_dispatch) 방식 권장, 저장소 Secrets는 사용자가 등록
- **로그인 실패 메시지 통일:** 비밀번호 오류와 미가입 이메일을 같은 메시지로 보여 가입 여부를 드러내지 않음. 이메일 인증·로그인 시도 제한은 MVP 제외
- **완료 취소:** 허용(`completed` → `scheduled`). 단 수업일지가 있는 회차는 불가. 잘못 누른 경우는 흔하지만, 일지까지 쓴 회차는 실제로 진행된 것으로 봄
- **레슨권 소진:** 잔여 0이어도 자동 종료하지 않고 '소진' 표시. 종료는 강사가 직접, 새 레슨권 추가 시 이전 레슨권 종료를 제안. 진행 중 레슨권 여러 개 허용. 자동 종료는 완료 취소와 엮이면 상태를 되돌려야 해서 제외
- **시작 전 완료:** 허용하되 확인을 받음. 시연 때 방금 등록한 회차도 바로 완료할 수 있어야 하기 때문
- **수강생 보관:** 남은 `예정` 회차는 확인 후 삭제, 완료·휴강·결석 기록은 보존
- **ML 기능 (과제 조건):** 수강생 메시지를 휴강 요청·보강 요청·일정 변경·일반 메시지로 분류. 예측은 참고용이고 일정·상태를 자동으로 바꾸지 않음. 외부 AI API·별도 추론 서버·GPU 없이 Django 안에서 직접 추론
- **모델 선택:** TF-IDF(글자 단위 1~3gram) + Logistic Regression. 데이터가 수백 건이라 단순 선형 모델이 적합, 한국어 조사·어미 문제를 형태소 분석기 없이 줄임(교차검증에서 단어 단위보다 macro F1 약 0.07 높음)
- **학습과 추론 분리:** 학습은 개발 PC, 검증된 모델 파일(70KB)을 git에 커밋해 이미지에 포함. 서버·CI는 재학습하지 않고 `ml.verify`로 호환성만 확인. 학습 자동화는 발표 전 제외
- **수강생 쪽 화면:** MVP는 A안(강사가 가상 수강생 메시지 등록). 수강생 전용 링크(B안)는 핵심 완료 후 여유 시, 수강생 계정(C안)은 발표 후. 데이터 구조는 양방향 전제(`sender`)
- **앱 이름 `inbox`:** `messages`는 `django.contrib.messages`와 앱 이름이 겹침
- **잔여 초과 일정:** 저장 후 예정 회차 수(새 회차 포함) > 잔여 회차이면 경고만 하고 저장 허용 (UC-06 "회차 초과" 경고와 같은 방식). PR #26 리뷰에서 '이상/초과' 표현이 문서마다 달라 초과(>)로 통일
- **CI 범위:** 지금은 린트+테스트만. Docker 이미지 빌드·스모크 테스트는 Dockerfile이 생기는 #5 이후 추가. CI용 환경변수는 실제 비밀값이 아닌 고정값을 워크플로에 직접 둠
- **회원가입 범위:** 이메일 인증·소셜 로그인은 MVP 제외
- **DB 접속 주소는 127.0.0.1:** Windows에서 `localhost`가 IPv6(::1)로 먼저 연결을 시도해 테스트 DB 생성 단계에서 멈춤(::1 쪽 5초 이상 대기). 포트를 127.0.0.1에만 열었으므로 접속도 127.0.0.1로 통일
- **설정 라이브러리 django-environ:** `.env` 읽기와 `DATABASE_URL` 해석을 패키지 하나로 처리
- **커스텀 User는 첫 마이그레이션 전에:** 나중에 바꾸면 마이그레이션이 매우 어려워 #4에 포함 (ERD 2-4). 회원가입·로그인 화면은 UC-01(#8)에서

- **메일 발송:** Gmail SMTP + 앱 비밀번호. 우선 개발자 개인 계정을 쓰고 나중에 전용 계정으로 교체 (`.env`만 변경)

- **보강 필요 표시:** 보강 없는 휴강·미차감 결석에 "보강 필요" 배지. 별도 필드 없이 보강 연결 유무로 판단
- **차감한 결석:** 보강 불가로 확정 (중복 차감 방지)
- **화면:** 모바일 우선(360px), 홈은 주간 일정(오늘 강조), 등록·수정 폼 공유, 상태 변경은 POST로만 처리(CSRF 보호)
- **홈 화면:** 월간 달력 + 선택한 날의 회차 목록이 기본, 주간 보기로 전환. 날짜 선택은 URL 파라미터로 처리해 JS 없이 동작
- **디자인·CSS:** 아이폰 캘린더처럼 여백·얇은 구분선·강조색 하나·시스템 글꼴. 프레임워크 기본 디자인을 덮어쓰는 수고가 더 커서 CSS는 직접 작성(CSS 변수로 관리)
- **라벨과 상태 (확정):** 둘 다 색으로 쓰면 섞여 읽기 어려워 역할을 나눔. 색은 강사가 정하는 라벨(8색 중 선택) 전용, 상태는 모양으로. 라벨은 '수강생 × 수업'인 레슨권에 붙여 수업 형태 구분과 사람 구분을 한 모델로 모두 지원
- **접근 정책 (PR #28 리뷰):** `LoginRequiredMiddleware`로 기본 로그인 필수(기본 거부), 로그인·회원가입·비밀번호 찾기만 공개. 새 화면에서 로그인 검사를 빠뜨려도 막힘
- **경고 후 저장 (PR #28 리뷰):** '그래도 저장' 2단계 대신 한 번에 저장하고 다음 화면에서 경고. 기존 규칙('경고만, 저장 허용')과 일치하고 중복 요청·재검증 문제가 생기지 않음
- **구현 순서 (PR #28 리뷰):** MVP 핵심(UC-01~07) 먼저, MVP 후속(UC-08·09, UC-15, UC-16)은 그다음. 라벨이 없어도 핵심 흐름이 동작하도록 설계
- **앱 구조:** `accounts`(User) / `students`(Student) / `lessons`(Enrollment, LessonSession). Enrollment는 잔여 계산이 회차와 붙어 있어 lessons에 둠
- **장소:** 회차마다 자유 메모로 적음. 장소 등록·지도 연동은 프로젝트 기간 이후. MVP의 정의("없어도 핵심 흐름이 끊기지 않는가")에 따라 장소 관리 화면은 MVP에서 제외
- **발표 필수/권고 구분 (PR #30 리뷰, OPERATIONS.md):** 과제 필수조건(직접 학습한 ML 모델의 Django 웹 추론, #32)이 추가되어 발표 필수 = ML 학습·평가 기록·모델 버전·웹 추론 스모크 테스트 + 핵심 흐름 + CI + 외부 배포(DB 비공개·비밀정보 분리 포함). 외부 HTTPS·이미지 롤백 검증·백업 복구 훈련은 권고로 내림. 모델은 앱 이미지에 포함해 앱과 함께 배포·롤백(호환성 유지)
- **HTTPS 예외 범위 (PR #30 재검토):** HTTPS 생략은 실제 개인정보 없는 격리 시연에만 허용. HTTP 시연 시 데모 계정은 재사용하지 않는 시연 전용 비밀번호 사용. 실제 정보 입력 전에는 HTTPS·보안 쿠키 필수
