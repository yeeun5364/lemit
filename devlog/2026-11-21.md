## 결정 사항
- 롤백 뒤에는 자동 배포를 **보류**하고 수동 deploy로만 다시 시작한다. 롤백과 자동 배포가 어떤 순서로 실행되든 끝 상태가 같아야 하고(장애 대응 중 요청한 롤백이 덮이지 않음), 다시 배포할 시점은 원인을 확인한 사람이 정하는 것이 안전하다고 판단
- 직렬화는 GitHub 그룹 하나에 기대지 않고 서버 잠금으로 한다. GitHub 그룹은 대기 1개만 남겨 롤백을 지킬 수 없기 때문

## 이슈 / 고민
- GitHub concurrency의 대기·취소 동작은 로컬에서 재현할 수 없음 → 정책 검사로 그룹 식을 고정하고, 실제 동작은 CD.md §6 첫 시험에서 확인해야 함 (아직 안 함)
- 서버 강제 명령을 갱신하기 전에는 `deploy-auto`가 거부됨(배포 안 됨, 안전한 쪽 실패)
