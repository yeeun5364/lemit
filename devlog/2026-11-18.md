## 결정 사항
- **AI 기능 없이 진행**: 과제 조건상 AI/MLOps 필수 아님 확인. MVP는 웹서비스 핵심 흐름에 집중 (#3)
- ERD(초안): 보강은 상태가 아니라 `makeup_for` 연결로 표현, 잔여 회차는 저장하지 않고 계산, MVP에서는 기획서의 `Lesson`을 `Enrollment`에 합침, 커스텀 User(이메일 로그인)로 시작 → **확정**
- 미성년자 수강생은 보호자 연락처 필수. 생년월일 대신 `is_minor`만 받아 개인정보 최소화 (ERD 2-7, UC-02 반영)
- 컨테이너는 서비스에 필요한 것만: `web`(Django) + `db`(PostgreSQL 18). 정적 파일은 WhiteNoise로 처리해 nginx 컨테이너 생략
- 새 컨테이너는 healthcheck(`/healthz/`, `pg_isready`)와 스모크 테스트로 정상 동작을 확인 (#5, #6, #7에 반영)
- 서비스명 **LEMIT(레밋)** 확정 (Lesson + Meet)
- 1차 사용자: 개인 레슨을 운영하는 프리랜서 강사
- 핵심 문제: 유동적인 일정·휴강·보강과 수업 회차 관리
- 초기 아키텍처 방향: Django 모놀리스 + PostgreSQL (설계안)
- 발표용 MVP 흐름: 수강생 등록 → 일정 등록 → 일정 조회 → 완료 처리 → 진행·잔여 회차 확인
