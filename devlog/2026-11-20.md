## 결정 사항
- **홈 = 대시보드, 달력은 '수업 일정' 화면으로 (#45):** 로그인 직후 오늘 할 일(메시지 확인·수강생)을 먼저 보여준다. SCREENS.md S00 추가, S05 URL은 UC-05 구현 때 결정
- **없는 기능은 '준비 중'으로만 표시:** 일정 기능이 없으므로 오늘 수업 수·일정 목록·일정 화면 URL을 만들지 않는다
- **프레임워크 없이 CSS 변수 + 작은 JS 하나(`static/js/app.js`):** 기존 방식 유지, JS 없이도 모든 기능 동작(점진적 향상)
- **다크 모드 제거:** 지정 팔레트가 밝은 테마 기준. 필요하면 같은 변수에 값을 추가해 후속 진행
- **방화벽 변경 API = 전체 다시 쓰기(put) + 다시 읽기·검증:** 동작이 문서로 보장되는 API만 쓴다. Lightsail에는 조건부 쓰기가 없어 다시 읽기와 쓰기 사이의 아주 짧은 틈은 남으므로, 배포 중 콘솔 변경을 피하고 실패 시 수동 복구 절차를 둔다
- **buildx는 패키지를 지우지 않고 우선순위가 높은 경로에 설치 (#48):** docker CLI는 `/usr/local/lib/docker/cli-plugins`를 `/usr/libexec/...`보다 먼저 찾음. 패키지 업데이트와 충돌하지 않고 되돌리기 쉬움(파일 하나 삭제)
- **브랜치 보호:** Docker 검사도 병합 필수, 관리자도 예외 없음. CI 장애로 병합이 막히면 설정에서 잠시 끈다
- **실제 복구(운영 DB 되돌리기)는 자동화하지 않음:** 백업 이후 데이터가 사라지므로 절차만 문서화(web 정지 → 현재 상태 백업 → pg_restore --clean → 재배포 → 확인). 백업은 같은 디스크에 있으므로 Lightsail 자동 스냅샷을 함께 켜도록 권장
- **자동 백업 = systemd 타이머:** Amazon Linux 2023에는 cron이 기본으로 없음
- **복원 점검 임시 DB는 실행마다 새로 만들고 자기 것만 지움 (PR #46 리뷰):** 고정 이름을 지우는 방식은 같은 이름의 다른 DB나 동시 실행을 파괴할 수 있음. 강제 종료로 남은 DB는 진행 중인 점검일 수 있어 자동 삭제하지 않음
- **캐시는 AI 모델에만 (#51):** 측정상 효과 확인(서버 약 10~17배). 수업·회차·메시지 데이터와 `/healthz/`는 캐시하지 않음(강사별 화면이라 재사용 적음, 최신성 중요, 측정상 느린 곳 없음). Redis 같은 별도 캐시 서버는 2GB 서버에 장애 지점만 늘려 도입하지 않음. 느려짐이 측정되면 다시 검토
- **보관된 수강생에게는 레슨권을 추가하지 않음 (UC-03):** 보관 해제 후 추가. 실수로 보관 수강생에 기록이 쌓이는 것을 막음
- **라벨은 강사 계정 삭제 시 함께 삭제(CASCADE):** 개인 설정이라 기록 보존 대상이 아님. 수강생이 있으면 계정 삭제 자체가 PROTECT로 막힘
