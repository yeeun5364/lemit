## 추가 작업 (PR #58 4차 리뷰)
- 롤백 뒤 자동 배포 보류를 **수동 배포가 성공한 뒤에만** 풀도록 변경 (`scripts/ci_deploy.sh`)
  - 수동 deploy는 `deploy.sh`를 exec 대신 자식으로 실행하고 종료 코드 0일 때만 해제. `deploy.sh`는 모든 실패 경로(사전 점검·빌드·check --deploy·스모크 실패 후 자동 롤백·공개 경로 확인 실패)를 0이 아닌 코드로 끝냄을 코드로 확인
  - 시작할 때 본 보류 내용과 성공 후 내용이 같을 때만 지움 → 배포하는 사이 새 롤백이 건 보류는 유지. 보류 내용에 요청 PID를 넣어 보류마다 구분. 호환 모드(예전 deploy.sh)는 성공 후 잠금을 다시 잡고 확인
- 테스트(`test_ci_deploy.sh` 62개 통과, WSL Ubuntu): 실패 → 유지 / 성공 → 해제 / 배포 중 새 롤백 보류 → 새 보류 유지를 새·예전 작업 트리 각각에서, 실패 뒤 자동 배포가 계속 건너뛰는지, DRY_RUN(배포 안 함)은 해제하지 않는지
- 변형 시험은 사용자 요청대로 **scratchpad 임시 복사본에서만** 실행: 복사본의 `ci_deploy.sh`에 "배포 전에 보류 삭제"를 넣으면 6개 실패로 잡힘. 시험 전후 원본 3개 파일(sha256) 동일 확인, 복사본 삭제
