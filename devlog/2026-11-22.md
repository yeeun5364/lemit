## 추가 작업 (PR #58 4차 리뷰)
- 롤백 뒤 자동 배포 보류를 **수동 배포가 성공한 뒤에만** 풀도록 변경 (`scripts/ci_deploy.sh`)
  - 수동 deploy는 `deploy.sh`를 exec 대신 자식으로 실행하고 종료 코드 0일 때만 해제. `deploy.sh`는 모든 실패 경로(사전 점검·빌드·check --deploy·스모크 실패 후 자동 롤백·공개 경로 확인 실패)를 0이 아닌 코드로 끝냄을 코드로 확인
  - 시작할 때 본 보류 내용과 성공 후 내용이 같을 때만 지움 → 배포하는 사이 새 롤백이 건 보류는 유지. 보류 내용에 요청 PID를 넣어 보류마다 구분. 호환 모드(예전 deploy.sh)는 성공 후 잠금을 다시 잡고 확인
- 테스트(`test_ci_deploy.sh` 62개 통과, WSL Ubuntu): 실패 → 유지 / 성공 → 해제 / 배포 중 새 롤백 보류 → 새 보류 유지를 새·예전 작업 트리 각각에서, 실패 뒤 자동 배포가 계속 건너뛰는지, DRY_RUN(배포 안 함)은 해제하지 않는지
- 변형 시험은 사용자 요청대로 **scratchpad 임시 복사본에서만** 실행: 복사본의 `ci_deploy.sh`에 "배포 전에 보류 삭제"를 넣으면 6개 실패로 잡힘. 시험 전후 원본 3개 파일(sha256) 동일 확인, 복사본 삭제

## 추가 작업 (태그 파이프라인: test → train → parity → image → release → deploy)

- 요청: 버전 태그 push 시 여섯 단계를 GitHub Actions 한 실행 화면에서 순서대로, 학습한 모델과 시험한 이미지가 Lightsail까지. 별도 worktree(`../lemit-pipeline`, 브랜치 `feat/tag-pipeline`)에서 작업, 태그·설정·배포·병합은 하지 않음
- 구조: Release tag(GitHub-hosted, 읽기 전용)를 가벼운 진입점으로 두고, `deploy.yml`(workflow_run → 언제나 main의 파일) 한 실행에 `0. plan → 1. test → 2. train → 3. parity → 4. image → 5. release → 6. deploy`. 앞 작업이 실패하면 뒤 작업은 실행 안 됨(needs, 상태 함수 금지). 수동 check·deploy·rollback은 plan·deploy만
- 대상 커밋: `github.sha`(workflow_run에서는 main 최신)와 태그 커밋(`needs.plan.outputs.sha`)을 구분. 모든 checkout에 ref 명시 + HEAD 재확인, 이미지 라벨·Release·서버 요청에 같은 값
- 권한: test·train·parity `contents: read`, image만 `packages: write`(빌드·시험 뒤 로그인), release만 `contents: write`(저장소 코드 안 받음), 배포 키는 production 승인 뒤 deploy만
- parity: 기존에 parity 단계는 없었고 `ml.verify`의 점수 재현(허용 1e-4)이 가장 가까움 → `ml/parity.py`로 같은 모델·같은 입력(검증 63 + 확인용 60) 예측을 비교(분류 전부 일치, 확률 ≤ 1e-6, macro F1 ≤ 1e-4). 학습 환경 ↔ Dockerfile 기반 이미지, 학습 환경 ↔ 게시할 이미지
- 이미지·릴리즈·서버: GHCR(`ghcr.io/yeeun5364/lemit-web`)에 실행마다 새 태그로 게시, digest로 다시 받아 시험한 이미지 ID와 비교. Release에 기계용 기록(`lemit-release` 블록) — 같은 기록이면 재사용, 다르면 덮어쓰지 않고 차이 표 + 실패. 서버 강제 명령 `deploy-image <태그> <커밋> <digest>`: 태그·main 포함·**Release 기록과 digest 일치** 확인 → 대상 커밋으로 바꾼 뒤 그 커밋의 `deploy.sh`를 `DEPLOY_IMAGE`로 실행(받기만, 빌드 없음, 라벨 커밋 확인, 실행 컨테이너 이미지 ID 확인, `current_image` 기록)
- 정책 검사 갱신: 기존 보호 조건(self-hosted 하나, PR·push 트리거 금지, 검증 작업 조건, production, concurrency 그룹, 러너에서 액션 금지) 유지 + 작업 순서·상태 함수·작업별 권한·Secret/Environment는 deploy만·checkout 대상 커밋·액션 SHA 고정·`deploy-tag`/`deploy-auto` 금지
